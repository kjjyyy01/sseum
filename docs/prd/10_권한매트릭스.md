# 권한 매트릭스 (MVP §10 승계)

역할은 `anon`·`user` 둘뿐. 관리자 없음. 타인 리소스는 RLS로 비가시 → 404 `ERR-COMMON-003`(PRD-공통규약).

| 역할 | 리소스 | 본인 | 타인 | RLS 정책 | 검증 TC |
| ---- | ---- | ---- | ---- | ---- | ---- |
| user | transactions | R/W | — | `user_id = auth.uid()` (SELECT/INSERT/UPDATE) | TC-TXN-002-05, TC-TXN-003-05, TC-INPUT-001-05 |
| user | categories | R/W | — | 동일 | TC-CAT-001-05 |
| user | subscriptions | R/W | — | 동일 | TC-SUB-003-05 |
| user | subscription_checkins | R/W | — | `EXISTS(subscriptions s WHERE s.id=subscription_id AND s.user_id=auth.uid())` | TC-SUB-002-05 |
| user | consents | R / W(INSERT만) | — | `user_id = auth.uid()`, UPDATE/DELETE 정책 없음 | TC-LOGIN-002-05 |
| user | rate_limits | — (서버 전용) | — | 정책 없음 → anon/user 접근 불가, service role만 | — |
| user | 계정(auth.users) | R, 삭제 | — | Supabase Auth; 삭제는 서버 service role | TC-SET-001-05 |
| anon | 전부 | — | — | 정책 없음 | TC-HOME-001-05 |
| anon | `/login`,`/terms`,`/privacy` | R | — | 정적 | — |

- 각 행의 "타인" 거부 케이스는 위 TC에서 **다른 사용자 세션으로 실제 id를 지정해** 404를 확인한다(IDOR).
- DELETE는 SQL DELETE 정책을 두지 않는다(거래는 소프트 삭제, 계정 삭제는 service role 경로).
