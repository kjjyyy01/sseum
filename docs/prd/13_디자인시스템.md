## 3. 모션 규칙 (GSAP) — SSOT

### 3.1 설치·경계
- 패키지: `gsap`, `@gsap/react`. 전 플러그인 무료(2025~). 사용 플러그인: 코어 + `Flip`(M-05·M-08) + `ScrollTrigger`(M-09 랜딩만). `SplitText`는 히어로 H1 1곳만, 분할 후 원문 `aria-label` 유지.
- **Client Component에서만** import. 훅은 `useGSAP(() => {...}, { scope: ref, dependencies })` 고정 — 컨텍스트 자동 cleanup(언마운트 시 트윈·ScrollTrigger 전부 kill). `useEffect` + 수동 gsap 금지.
- 서버 컴포넌트 트리에 GSAP 대상이 있을 때: 대상 요소만 얇은 클라이언트 래퍼(`<Animate name="M-01">`)로 감싼다. 데이터 fetch는 래퍼 바깥 서버에 남긴다.

### 3.2 절대 규칙 (실패 조건)
1. **LCP 요소는 가시 상태로 시작한다.** 각 화면 LCP 후보(SCR-001 첫 WatchCard 또는 Empty 제목 / SCR-006 H1 / SCR-003 첫 그룹)는 `opacity:0`·`visibility:hidden`·`y` 오프셋으로 시작 금지. 등장 모션은 LCP 요소를 제외한 주변 요소만.
2. **초기 숨김은 CSS가 아니라 GSAP `from()`으로만.** SSR HTML은 항상 완전 가시 상태(JS 없이도 보임). `gsap.from`이 하이드레이션 직후 실행돼 짧은 FOUC가 생기는 요소는 `data-animate` 속성 + `html.js [data-animate]{opacity:0}` 조합으로만 예외 허용하며, `<html>`에 `js` 클래스를 붙이는 인라인 스크립트는 `<head>` 첫 줄(no-JS면 클래스 없음 → 보임). LCP 요소에는 이 예외도 금지.
3. **`prefers-reduced-motion: reduce`** → `gsap.matchMedia()`로 전 모션을 즉시 완료 상태(`duration: 0` 또는 `gsap.set`)로 대체. 카운트업은 최종 숫자 즉시 표시. 검증은 chrome-devtools 에뮬레이션.
4. **입력 경로에 블로킹 모션 금지.** SCR-002에서 금액 입력·카테고리 탭·저장 사이에 대기시키는 트윈이 없어야 한다. 피드백(M-04)은 저장 응답 **후** 재생되며 사용자는 재생 중에도 즉시 닫거나 이동할 수 있다.
5. **duration 상한** 0.6s(랜딩 M-09만 1.2s). stagger 합계 0.8s 이내. 이징 기본 `power2.out`, 강조 `back.out(1.4)`.
6. **레이아웃 스래싱 금지**: transform·opacity만 애니메이션. width/height/top은 `Flip`으로.
7. `will-change`는 트윈 직전 GSAP가 관리, 수동 지정 금지.
8. 리스트 stagger는 md 이상에서만(`gsap.matchMedia`), base는 단일 페이드(성능·배터리).

### 3.4 파일 구조
```
lib/motion/
  index.ts        ← gsap.registerPlugin(Flip, ScrollTrigger, useGSAP), 공통 이징·duration 상수, reduceMotion matchMedia 헬퍼
  presets.ts      ← M-01~M-10 함수(각각 (targets, opts) => Timeline)
components/motion/
  Animate.tsx     ← 서버 트리에서 쓰는 얇은 클라이언트 래퍼 (name: MotionId)
```
모션 값(duration·ease·offset)은 `presets.ts`에만 둔다. 화면 컴포넌트에서 숫자 하드코딩 금지.
