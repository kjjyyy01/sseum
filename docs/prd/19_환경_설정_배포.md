# 환경 · 설정 · 배포

## 환경
| 환경 | 호스트 | 데이터 | 용도 |
| ---- | ---- | ---- | ---- |
| local | `next dev` | 해당 브라우저 localStorage | 개발 |
| production | Vercel main | 사용하는 브라우저 localStorage | 실사용 |

- 환경마다 origin이 다르므로 localStorage도 분리된다(로컬 데이터 ≠ 배포 데이터). 옮길 때는 설정의 백업 내보내기 → 가져오기.
- preview 환경은 선택. 쓰더라도 도메인이 배포마다 달라 데이터가 이어지지 않는다.

## 환경변수: 없음
v1.0.0의 Supabase·PostHog·Sentry 변수는 폐기. `.env*`는 계속 gitignore.

## 렌더링·빌드
- `next build` 출력: `/transactions`만 Dynamic(ƒ, month 정규화), 나머지 Static(○).
- ISR 미사용.
- GSAP는 Client Component에서만 import.
- 폰트: `next/font`(Pretendard Variable 로컬 + Space Grotesk) — 디자인시스템 SSOT.

## 개발 명령
| 명령 | 내용 |
| ---- | ---- |
| `npm run dev` / `build` / `lint` | Next.js 기본 |
| `npm run check` | 저장소 계산 규칙 자가 점검 (`src/lib/store.check.ts`) |

## 배포·롤백
- 작업 브랜치 → main 머지 = 프로덕션.
- 롤백: Vercel 이전 배포 "Promote to Production". 데이터는 브라우저에 있으므로 롤백해도 영향 없음 — 단, 저장 형식(`version`)을 올린 배포를 되돌릴 때는 PRD-마이그레이션 참고.
