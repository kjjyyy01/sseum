# 관측성 · 운영

| 항목 | 설정 |
| ---- | ---- |
| 에러 트래킹 | Sentry(Next.js SDK, 서버+클라). Server Action 실패는 `ERR-COMMON-001` 반환 전 `captureException`. 사용자 식별은 user id만 |
| 알림 | Sentry → 이메일 + (선택) Slack. 신규 이슈 즉시, 출시 준비에서 테스트 에러로 수신 확인 |
| 로그 | Vercel 함수 로그(7일). PII 로깅 금지(이메일·메모·금액) |
| 업타임 | Vercel 상태 + Supabase 상태 페이지. 별도 핑 없음 |
| 지표 | PostHog 대시보드 1개: H-01~H-03 (주 2회 확인, PLAN 런칭 후 루틴) |
| 백업 | Supabase 자동 일일 백업(플랜별 보존 확인, OQ-003). 복구 리허설 1회 |

## 런북
1. **장애 인지** — Sentry 알림 또는 사용자 피드백 → Vercel·Supabase 상태 페이지 확인.
2. **배포 원인** — Vercel 이전 배포 승격(롤백) → 확인 → 원인 커밋 revert.
3. **DB 원인** — Supabase 대시보드 → 최근 마이그레이션 확인 → 필요 시 `contract` 단계 롤백 SQL(PRD-마이그레이션).
4. **유출 의심** — PRD-보안및프라이버시 유출 대응 순서.
5. 사후: 트러블슈팅 당일 EOD 기록 + 해결 커밋에 원인·해결 한 줄.
