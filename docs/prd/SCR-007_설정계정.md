## 1. 개요
- **목적:** 계정 정보, 로그아웃, 계정 삭제(강제 트리거: 회원 기능), 법적 문서·피드백 링크.
- **구현 기능:** F-010 계정 삭제(+로그아웃)
- **렌더링:** `/settings` 동적 SSR(세션 이메일). 삭제 시트만 Client Component. 삭제는 service role 서버 경로.

## 3. 기능 요구사항
### REQ-SET-001: 계정 삭제 (P0)
- **AC-1 (정상):** Given 시트에 본인 이메일 정확 입력, When 삭제 확인, Then `deleteAccount({email_confirm})` → BR-012 순서로 전 데이터 하드 삭제 → `auth.admin.deleteUser` → PostHog person 삭제(best-effort) → EVT-ACC-001(삭제 직전 발화) → 세션 쿠키 삭제 → 302 `/login?deleted=1`.
- **AC-2 (검증 실패):** 이메일 불일치(대소문자 무시) → ERR-ACC-001(CPY-SET-003), 서버 호출 없음(클라) + 서버 재검증.
- **AC-3 (서버 오류):** 삭제 트랜잭션 실패 → 롤백(부분 삭제 없음) → ERR-ACC-002(CPY-SET-004) + 재시도. auth 삭제만 실패한 경우: 데이터는 이미 삭제됐으므로 Sentry 경보 + 사용자에게는 성공 처리 후 수동 정리(런북).
- **AC-4 (오프라인):** 버튼 비활성.
- **AC-5 (권한):** 세션 없음 → ERR-AUTH-004. 타인 계정 지정 불가(요청에 user id 없음, 세션에서만 결정). 10분 1회 rate limit(ERR-COMMON-004).

### REQ-SET-002: 로그아웃 (P0)
- **AC-1 (정상):** When 로그아웃, Then `signOut` 서버 세션 무효화 + 쿠키 삭제 → `/login`.
- **AC-2 (검증 실패):** 해당 없음.
- **AC-3 (서버 오류):** 쿠키만 삭제 후 `/login`(서버 세션은 만료로 소멸).
- **AC-4 (오프라인):** 쿠키 삭제 후 이동(서버 무효화는 다음 온라인 요청에서 실패해도 무해).
- **AC-5 (권한):** 세션 없음 → 이미 `/login`.

## 8. 데이터 변화
- **8.3 삭제:** 하드 삭제 순서 checkins → subscriptions → transactions → categories → consents → rate_limits(user 키) → auth.users. 단일 트랜잭션(auth 삭제 제외). 연쇄 CASCADE는 안전망.
- **8.4 조회:** 세션 이메일만.

## 9. API 호출
- **9.1 페이지 로드:** `getUser()` (세션)
- **9.2 사용자 액션:** `deleteAccount`, `signOut`
- **9.4 응답 처리:** 삭제 타임아웃 15s(대량 행), 멱등(2회째는 세션 없음 → 401)

## 13. 비기능
- **성능 예산:** 삭제 p95 ≤ 5s(일반 사용자)
- **보안:** service role은 `lib/supabase/admin.ts`에서만, 이메일 재확인, rate limit, 삭제 로그(Sentry info, user id만)
- **접근성:** destructive 버튼 대비 4.5:1, 시트 포커스 트랩, 처리 중 `aria-busy`
- **반응형:** 단일 컬럼 max 640
